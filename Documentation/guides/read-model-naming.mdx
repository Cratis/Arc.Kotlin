## How Arc names read-model collections

When Arc resolves a MongoDB read-model collection, it delegates to a `NamingPolicy` bean to convert the JVM type into a storage name. The `NamingPolicy` interface declares two methods:

- `getReadModelName(Class<?>)` — returns the collection name for a read-model type. Must be non-blank and stable across calls for the same type.
- `getPropertyName(String)` — returns the stored field name for a declared member name. The default implementation returns the name unchanged.

## Default policy

`DefaultNamingPolicy` is registered automatically by the MongoDB integration. It pluralizes the simple class name using [Evo Inflector](https://github.com/atteo/evo-inflector) (`org.atteo:evo-inflector`), except for a small built-in list of nouns where Evo Inflector and the kernel disagree: `Person` becomes `People` and `Index` becomes `Indices`, matching the kernel.

<ArcBackendTabs snippet="guides/read-model-naming/default-policy" variants="kotlin,java" />

Setting `pluralizeReadModelNames = false` returns the simple class name unchanged.

## The Chronicle Kernel is authoritative

Pluralization on the JVM uses Evo Inflector, a different library from the Humanizer library used by the .NET Chronicle Kernel. The two libraries agree on most common English nouns, but where they disagree on a specific noun the kernel is authoritative. The built-in corrections cover only the nouns measured so far; for any other noun that differs, the application must override the naming policy for that type so that the JVM reads from the collection the kernel writes to.

The cases pinned by `DefaultNamingPolicyTests` record what Evo Inflector actually produces. A library upgrade that changes a plural will fail those tests rather than silently moving a collection name.

## Override the policy for a specific type

Register a Spring bean that implements `NamingPolicy` and is annotated with `@ConditionalOnMissingBean` in your autoconfiguration, or supply it directly:

Arc calls the `NamingPolicy` bean on every collection lookup and does not cache the result. Keep `getReadModelName` cheap and deterministic, and cache inside your implementation when the computation is expensive.
